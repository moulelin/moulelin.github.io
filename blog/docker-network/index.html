Docker Network

September 22, 2022DockerNetworking

  • docker network connect: add a container to the specified network;

  • docker network create: create a network;

  • docker network disconnect: remove a container from the specified network;

  • docker network inspect: show detailed information about the specified network;

  • docker network ls: list all networks;

  • docker network rm: delete the specified network.

Once Docker is installed, there are three networks by default (docker network ls):

C:\Users\zsl-pc>docker network ls
NETWORK ID NAME DRIVER SCOPE
992344cd89fe bridge bridge local
06445f4f5774 host host local
2d964ece79b9 none null local

bridge: the default network for containers; once configured, it can communicate with the host and thereby reach the Internet.

host and none: these count as having no network (check with docker network inspect host: there is no subnet or gateway). Adding a container to either of them attaches it to a specific container network stack, and it cannot communicate with external networks.

Whenever you start a container with docker run, it gets a default network, namely bridge.

You can use the inspect command to see the containers in each network (here, the bridge network):

Newly created containers are placed on the bridge network by default, so they can communicate with each other via their IPs.

You can create a custom network, attach the containers that need to communicate to it, and access them by alias; IPs also work, but they are hard to remember
- 1. Create a network named test-net:
docker network create test-net

- 2. Run Redis on the test-net network with the alias redis
docker run -d --name redis --network test-net --network-alias redis redis:latest

- 3. Run the web project on the same network
docker run -p 8080:8080 --name test -v D:/test:/app --network test-net -d test:v1
